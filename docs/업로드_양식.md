# 문제 세트 업로드 양식 (JSON)

문제 실행기 웹의 **⬆️ 문제 업로드** 화면에 올리는 JSON 파일 양식이에요.
이 문서를 통째로 ChatGPT · Claude 같은 AI에게 붙여 넣고 "이 양식으로 ○○ 과목 문제 만들어 줘"라고 시켜도 되도록 썼어요(맨 아래 **7. AI에게 시킬 때**에 바로 쓸 지시문이 있어요).

## 1. 한눈에

- **파일 하나 = 세트 하나**예요. 확장자는 `.json`.
- 여러 파일을 **한 번에** 골라 올릴 수 있어요(한 번에 최대 20개, 파일당 1MB, 하루 10번까지).
- 파일을 고르면 바로 **검사 결과**가 나와요.
  - ❌ **오류**: 고쳐야 제출할 수 있어요.
  - ⚠️ **경고**: 제출은 되지만 관리자가 보고 판단해요(예: 해설 없음, 기존 문제와 비슷함).
- 제출한 세트는 **관리자가 승인하면** 모두에게 보여요. 반려되면 사유를 "내 제출"에서 볼 수 있어요.

## 2. 전체 예시

새 과목(데이터베이스, 3학년 1학기)의 기말고사 세트 예시예요. OX · 객관식 · 단답 · 용어가 다 들어 있어요.

```json
{
  "meta": {
    "subject": "데이터베이스",
    "exam": "기말고사",
    "kind": "일반문제",
    "title": "정규화 혼합 4문제",
    "unit": "7장",
    "topic": "함수 종속 · 정규형",
    "grade": 3,
    "semester": 1
  },
  "questions": [
    {
      "category": "정규화",
      "question": "제2정규형(2NF)은 부분 함수 종속을 제거한 형태이다.",
      "answer": true,
      "explanation": "1NF에서 기본키의 일부에만 종속되는 속성(부분 함수 종속)을 없애면 2NF가 된다."
    },
    {
      "category": "정규화",
      "question": "제3정규형(3NF)에서 제거하는 종속은?",
      "choices": ["부분 함수 종속", "이행 함수 종속", "다치 종속", "조인 종속"],
      "answer": 1,
      "explanation": "3NF는 이행 함수 종속(A→B, B→C일 때 A→C)을 제거한다."
    },
    {
      "category": "SQL",
      "question": "테이블을 삭제하는 DDL 명령어는? (영문 명령어만)",
      "answers": ["DROP", "DROP TABLE"],
      "displayAnswer": "DROP",
      "hint": "D로 시작해요",
      "explanation": "DROP은 테이블 구조까지 지우는 DDL이다. DELETE는 행만 지우는 DML이다."
    },
    {
      "category": "SQL",
      "question": "SELECT는 DDL에 속한다.",
      "answer": false,
      "explanation": "SELECT는 데이터를 조회하는 DML이다."
    }
  ],
  "terms": [
    {
      "terms": ["이행 함수 종속", "이행함수종속", "transitive dependency"],
      "group": "7장",
      "desc": "A→B이고 B→C일 때 A→C가 성립하는 종속"
    }
  ]
}
```

> 이미 있는 과목(예: 운영체제)에 올릴 때는 `grade` · `semester`를 **빼세요**.

## 3. meta (세트 정보)

| 필드 | 필수 | 값 | 설명 |
|---|---|---|---|
| `subject` | ✅ | 문자열 | 과목명. **이미 있는 과목은 한 글자도 다르지 않게** 쓰세요("운영체제" ≠ "OS" ≠ "운영 체제"). 지금 있는 과목 목록은 업로드 화면 아래 "지금 있는 과목"에서 볼 수 있어요. `/` · `\` 는 쓸 수 없어요. |
| `exam` | ✅ | `"중간고사"` 또는 `"기말고사"` | 어느 시험 메뉴에 들어갈지. |
| `kind` | ✅ | `"일반문제"` · `"모의고사"` · `"기출"` · `"단어집"` | 분류. `단어집`이면 `terms`가 꼭 있어야 해요. |
| `title` | ✅ | 문자열 | 세트 카드 제목. 예: `"4장 스케줄링 OX 20문제"` |
| `unit` | | 문자열 | 장 · 단원(예: `"4장"`). 같은 장은 표기를 똑같이 쓰세요. 쓸 거면 빈 문자열은 안 돼요. |
| `topic` | | 문자열 | 카드 부제(예: `"선점 · 비선점"`). |
| `grade` | 새 과목이면 ✅ | 1 이상의 정수 | 학년. 이미 있는 과목이면 빼세요(적었는데 기존 값과 다르면 오류). |
| `semester` | 새 과목이면 ✅ | `1` 또는 `2` | 학기(계절학기 없음). 숫자로 쓰세요(`"1"` ❌). |

최상위에는 `meta` · `questions` · `terms` 세 개만 둘 수 있어요. `questions`와 `terms` 중 **적어도 하나는 비어 있지 않아야** 해요.

## 4. 문항 쓰는 법

문항 유형은 따로 적지 않아요. **모양을 보고 자동으로 판별**해요.

| 이렇게 쓰면 | 유형 |
|---|---|
| `answer`가 `true` 또는 `false` (따옴표 없이) | OX |
| `choices`(보기 배열)가 있음 | 객관식 |
| 둘 다 아님 | 단답 |

모든 문항에 쓸 수 있는 필드: `category`(소주제 배지, 예 `"스케줄링"`), `question`(필수), `explanation`(해설), `hint`(힌트, 단답에서 주로 사용).
이 밖의 필드는 넣으면 **오류**예요.

### OX

```json
{ "category": "스케줄링", "question": "FCFS는 선점형 스케줄링이다.", "answer": false,
  "explanation": "FCFS는 비선점형이다." }
```

- `answer`는 **따옴표 없는** `true` / `false`. `"true"`처럼 따옴표를 붙이면 오류예요.
- 한 문장에 판단할 사실은 하나만.

### 객관식

```json
{ "category": "교착상태", "question": "교착상태의 필요조건이 아닌 것은?",
  "choices": ["상호 배제", "점유와 대기", "선점", "환형 대기"], "answer": 2,
  "explanation": "필요조건은 비선점이다." }
```

- `answer`는 **0부터 세는 번호**예요. 첫 번째 보기 = `0`, 세 번째 보기 = `2`. (화면에는 1번부터 보여요.)
- 보기 앞에 `①`, `1.`, `1)` 같은 번호를 **붙이지 마세요**(오류). 번호는 화면이 붙여요.
- 같은 보기를 두 번 쓰면 오류예요. 보기는 **4개**로 쓰세요.

### 단답

```json
{ "category": "스케줄링", "question": "작업시간이 가장 짧은 프로세스를 먼저 실행하는 비선점 스케줄링은?",
  "answers": ["SJF", "최단 작업 우선", "최단작업우선", "Shortest Job First"], "displayAnswer": "SJF",
  "hint": "Shortest …", "explanation": "SJF는 평균 대기시간이 가장 짧다." }
```

- `answers`: 정답으로 **인정할 표기를 전부** 넣는 배열이에요.
- 채점은 **정확히 일치**해야 정답이에요. 앞뒤 공백, 영문 대소문자, 연속 공백만 무시하고 **띄어쓰기 유무는 구분**해요. 그래서 `"최단 작업 우선"`과 `"최단작업우선"`을 둘 다 넣어야 해요.
  - 넣을 것: 띄어쓰기 변형, 약어 · 풀네임, 한글 · 영문, 흔한 다른 표기.
  - 숫자 답이면 단위 있는 것 · 없는 것(`"8"`, `"8ms"`), 분수 · 소수(`"43/5"`, `"8.6"`)를 다 넣고, 질문에 `(숫자만)`처럼 입력 형식을 적어 주세요.
- `displayAnswer`(선택): 틀렸을 때 보여 줄 대표 정답. 없으면 `answers`의 첫 번째가 보여요.
- `answers`가 비어 있으면 오류예요.

### 용어 (`terms`, 단어 암기 테스트용)

```json
{ "terms": ["SJF", "최단 작업 우선", "최단작업우선"], "group": "4장",
  "desc": "작업시간이 가장 짧은 프로세스를 먼저 실행하는 비선점 스케줄링" }
```

- `terms`: 첫 번째가 **대표 표기**, 나머지는 인정할 다른 표기. 한 글자 표기는 넣지 마세요(경고).
- `desc`: 용어를 안 보고 읽어도 **그 용어 하나로 답이 정해지는 한 줄 정의**. 설명 안에 정답 용어를 그대로 쓰지 마세요. 없으면 경고(단어 암기 테스트에 안 나와요).
- `group`: 장 이름. `meta.unit`과 같은 표기로(예: `"4장"`).
- 쓸 수 있는 필드는 `terms` · `group` · `desc` 세 개뿐이에요.

## 5. 넣으면 안 되는 것

| 넣으면 안 되는 것 | 이유 |
|---|---|
| 위에 없는 필드(예: `type`, `number`, `score`) | 모르는 필드는 오류예요. |
| `id` · `uploader` · `practice` | 서버가 승인할 때 직접 붙이는 값이에요. |
| `registerPractice(` 라는 글자 (어디든) | 시스템이 연습 메뉴 코드로 오인해요. 오류예요. |
| HTML 태그(`<b>`, `<br>` 등) | 그대로 글자로 보여요. 줄바꿈은 문자열 안에 `\n`으로 쓰세요. |
| 한 파일 안에 똑같은 질문 두 번 | 오류예요(띄어쓰기만 다른 것도 같은 질문으로 봐요). |

JSON 문법도 지켜야 해요: 문자열은 큰따옴표 `"…"`, 마지막 항목 뒤에 쉼표 금지, 주석(`//`) 금지. 문자열 안의 큰따옴표는 `\"`로 쓰세요.

## 6. 좋은 문제 기준

- **해설(`explanation`)은 꼭** 1~2문장으로 써 주세요(없으면 경고). 정답인 이유를 적어요.
- **OX**: 참 · 거짓 비율을 40~60%로 맞춰 주세요. OX가 10개 이상인데 한쪽이 70%를 넘으면 경고가 떠요. 거짓 문항은 헷갈리기 쉬운 비교 · 함정에서 만드세요.
- **객관식**: 보기 4개, 정답 위치(0~3)를 고르게 섞기. 오답 보기는 같은 범주의 그럴듯한 것으로. "모두 옳다" · "정답 없음" 같은 보기는 쓰지 않기. 오답 보기 중에 사실 맞는 게 섞이지 않게.
- **단답**: 답이 **용어 하나나 숫자 하나로 딱 정해지는** 질문만. "설명하시오" 같은 서술형은 안 돼요.
- **한 파일 안에서** 한 문항이 다른 문항의 답을 알려 주지 않게(같은 개념을 객관식과 단답으로 동시에 내지 않기).
- 질문이 정답을 알려 주지 않게.
- 수업 내용과 다른 일반 지식으로 답이 갈리는 문제는 피하기.
- 이미 올라온 문제와 80% 넘게 비슷하면 경고가 떠요. 같은 사실을 참 · 거짓만 뒤집은 것도 비슷한 문제예요.

## 7. AI에게 시킬 때

이 문서 전체를 붙여 넣은 다음, 아래 지시문의 `[ ]` 부분만 바꿔서 이어 붙이세요.

```
위 "문제 세트 업로드 양식"을 정확히 지켜서 문제 세트 JSON을 만들어 줘.

- 과목(subject): [운영체제]
- 시험(exam): [기말고사]
- 분류(kind): [일반문제]
- 제목(title): [7장 메모리 관리 혼합 30문제]
- 단원(unit): [7장]
- 새 과목이면 학년(grade) · 학기(semester): [없음 / 3학년 1학기]
- 범위 · 내용: [아래 붙여 넣은 강의 요약 / 교재 7장 페이징 · 세그멘테이션 · 페이지 교체]
- 개수: [OX 15개, 객관식 5개, 단답 10개], 용어(terms): [핵심 용어 10개]

규칙:
1. 범위 · 내용에 있는 사실만 써. 모르는 건 지어내지 마.
2. OX 참 · 거짓은 40~60%, 객관식은 보기 4개 · answer는 0부터 세는 번호 · 정답 위치를 고르게.
3. 단답은 답이 용어 하나로 정해지게 하고, answers에 띄어쓰기 · 약어 · 한영 변형을 전부 넣어.
4. 모든 문항에 category와 1~2문장 explanation을 넣어.
5. 양식에 없는 필드(id, type 등)는 넣지 마. 보기 앞에 번호 붙이지 마.
6. 설명 없이 JSON만 출력해. 코드 블록 하나에 담아서.
```

만든 JSON은 메모장 등에 붙여 넣고 `이름.json`으로 저장하면 돼요(인코딩 UTF-8). 문항이 많으면 세트를 여러 파일로 나눠도 돼요.

## 8. 올리는 방법

1. 웹에 로그인하고 **⬆️ 문제 업로드**로 가요.
2. **파일 고르기**에서 JSON 파일을 하나 또는 여러 개 골라요. 처음이면 **📄 예시 JSON 내려받기**로 견본을 받아 고쳐 써도 돼요.
3. 파일마다 **검사 결과**가 나와요. ❌ 오류가 있으면 메시지(몇 번 문항, 무엇이 문제인지)를 보고 고친 뒤 다시 골라요. ⚠️ 경고만 있으면 제출할 수 있어요.
4. **제출하기**를 눌러요.
5. **내 제출**에서 상태를 봐요: 대기 → 승인(모두에게 보임) 또는 반려(사유 표시). 대기 중이면 취소할 수 있어요.
6. 반려되면 사유대로 고쳐서 새로 올려 주세요. 승인된 세트의 오류는 문항 화면의 🚩 신고로 알려 주세요.
