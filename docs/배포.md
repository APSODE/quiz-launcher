# 배포 안내 (Docker)

서버에 레포를 clone 하고 `docker compose up -d` 로 띄운다. 컨테이너 하나가 API 서버와 웹 화면을 함께 서비스한다. 설계는 `docs/설계_v2.md` 15장.

## 구성

```
인터넷 ─ https ─ 리버스 프록시(Caddy · nginx 등, 직접 운영) ─ http ─ 127.0.0.1:8787  컨테이너 app
                                                                     ├─ API (/api/*) + 웹 정적 파일
                                                                     └─ 볼륨 quiz-data (/data)
                                                                          ├─ db/quiz.sqlite   계정 · 풀이 · 업로드 대기 · 신고 · 댓글
                                                                          ├─ content/         콘텐츠 작업 사본 (처음 시작할 때 clone)
                                                                          └─ known_hosts
GitHub ─ push webhook ─→ /api/webhooks/github → 컨테이너가 content/ 를 pull
컨테이너 ─ 승인 커밋 push (배포 키) ─→ GitHub
```

- 이미지에는 앱 코드만 들어간다. 문제 내용은 컨테이너가 `/data/content` 에 따로 clone 하고, 이후 webhook 으로 최신 상태를 유지한다. 서버에 clone 한 레포 폴더는 **이미지 빌드용**일 뿐 콘텐츠로 쓰지 않는다.
- 승인한 업로드는 컨테이너 안의 작업 사본에서 커밋되고(pre-commit 훅 = `check.js` · 묶음 파일 생성이 그대로 돈다) GitHub 로 push 된다.

## 처음 설치

준비물: Docker Engine + Compose 플러그인, 도메인과 https 리버스 프록시.

```sh
# 1) 레포 받기
git clone https://github.com/APSODE/quiz-launcher.git
cd quiz-launcher

# 2) 배포 키 만들기 (컨테이너가 push 할 때 쓴다)
mkdir -p secrets
ssh-keygen -t ed25519 -N "" -C quiz-server -f secrets/deploy_key
cat secrets/deploy_key.pub
#   → GitHub 레포 Settings → Deploy keys → Add deploy key 에 붙여 넣고 "Allow write access" 체크

# 3) 설정 파일
cp .env.example .env
#   PUBLIC_ORIGIN, GITHUB_WEBHOOK_SECRET(openssl rand -hex 32) 등을 채운다

# 4) 빌드 · 실행
docker compose up -d --build
docker compose logs -f app        # "콘텐츠 clone" 과 서버 시작 로그 확인

# 5) 첫 관리자 계정 만들기
docker compose exec app node apps/server/scripts/admin-create.ts <아이디> <닉네임> <비밀번호>
```

### GitHub webhook 등록

레포 Settings → Webhooks → Add webhook

| 항목 | 값 |
|---|---|
| Payload URL | `<PUBLIC_ORIGIN>/api/webhooks/github` |
| Content type | `application/json` |
| Secret | `.env` 의 `GITHUB_WEBHOOK_SECRET` |
| Events | Just the push event |

등록하면 GitHub 가 `ping` 을 보낸다. Recent Deliveries 에 200 이 찍히면 연결된 것이다. 이후 push 하면 몇 초 안에 웹에 반영된다(관리자 화면 → 콘텐츠 상태에서 마지막 수신 시각 확인).

### 리버스 프록시 예시 (Caddy)

```
quiz.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

컨테이너 포트는 기본으로 `127.0.0.1` 에만 열린다(`.env` 의 `HOST_BIND` · `HOST_PORT`). 프록시 없이 바로 열려면 `HOST_BIND=0.0.0.0` 으로 바꾸되, 그 경우 `PUBLIC_ORIGIN` 을 `http://<주소>:<포트>` 로 맞춘다(https 가 아니면 쿠키에 Secure 가 붙지 않는다).

## 환경 변수 (`.env`)

| 이름 | 필수 | 뜻 |
|---|---|---|
| `PUBLIC_ORIGIN` | O | 서비스 주소. 쿠키 · Origin 검사 · 초대 링크에 쓰인다 |
| `CONTENT_REPO_URL` | O | 콘텐츠 레포 주소(쓰기 권한). SSH + 배포 키 권장, 또는 `https://x-access-token:<토큰>@github.com/...` |
| `CONTENT_BRANCH` | | 기본 `master`(APSODE/quiz-launcher 의 기본 브랜치). 테스트 콘텐츠 레포는 `main` |
| `GITHUB_WEBHOOK_SECRET` | O | webhook 서명 검증 |
| `GIT_AUTHOR_NAME` · `GIT_AUTHOR_EMAIL` | | 승인 커밋 작성자 |
| `UPLOAD_MAX_FILE_BYTES` · `UPLOAD_MAX_FILES` · `UPLOAD_DAILY_LIMIT` | | 업로드 제한(기본 1MB · 20개 · 하루 10건) |
| `HOST_BIND` · `HOST_PORT` | | 호스트에서 열 주소 · 포트(기본 `127.0.0.1:8787`) |

이미지에 고정된 값: `PORT=8787`, `DATABASE_PATH=/data/db/quiz.sqlite`, `CONTENT_DIR=/data/content`, `WEB_DIST=/app/apps/web/dist`.

## 운영

| 할 일 | 명령 |
|---|---|
| 앱 업데이트 | `git pull && docker compose up -d --build` (문제 내용은 webhook 으로 따로 반영되므로, 앱 코드가 바뀔 때만) |
| 로그 | `docker compose logs -f app` |
| 정지 · 시작 | `docker compose stop` · `docker compose start` |
| 콘텐츠 수동 새로고침 | 관리자 화면 → 콘텐츠 → 새로고침 (webhook 이 실패했을 때) |
| 백업 | 아래 |

### 백업 · 복원

보존할 것은 SQLite 파일 하나다(문제 내용은 GitHub 에 있다).

```sh
# 백업 (실행 중에도 안전한 온라인 백업)
docker compose exec app node -e "const {DatabaseSync}=require('node:sqlite');new DatabaseSync(process.env.DATABASE_PATH).exec(\"VACUUM INTO '/data/db/backup.sqlite'\")"
docker compose cp app:/data/db/backup.sqlite ./backup-$(date +%F).sqlite

# 복원
docker compose stop app
docker compose cp ./backup-YYYY-MM-DD.sqlite app:/data/db/quiz.sqlite
docker compose start app
```

### 문제가 생기면

| 증상 | 확인 |
|---|---|
| 시작하자마자 종료 | `docker compose logs app` — `.env` 필수 값 누락이면 어떤 값인지 출력된다 |
| clone · push 실패 (`Permission denied (publickey)`) | 배포 키가 `secrets/deploy_key` 에 있는지, GitHub 에 "Allow write access" 로 등록했는지 |
| push 해도 웹에 안 보임 | GitHub Webhooks → Recent Deliveries 응답 코드(401 = 시크릿 불일치), 관리자 화면의 pull 경고 |
| 승인했는데 "훅 실패" | 관리자 화면에 훅 출력이 보인다. 업로드 내용 문제면 반려 후 다시 받는다 |
| 작업 사본이 꼬임 | 관리자 화면 pull 경고 확인 후, 최후 수단: `docker compose exec app rm -rf /data/content` → `docker compose restart app` (다시 clone 된다. DB 는 그대로) |

## 저사양 서버 배포 (오라클 프리티어 AMD Micro, 1GB)

### 왜 따로인가

AMD Micro 는 메모리 1GB 에 스왑이 없다. 서버에서 `--build` 하면 의존성 설치 · 웹 빌드 중에 메모리가 모자라 멈출 수 있다. 그래서 **같은 x86_64 PC 에서 이미지를 빌드해 보내고, 서버는 실행만 한다.** 앱 실사용 메모리는 약 75MB 다.
ARM(Ampere A1, 6GB 이상)이면 위의 기본 절차(서버에서 `docker compose up -d --build`)를 그대로 써도 된다.

파일은 `deploy/oracle/` 에 있다.

| 파일 | 역할 |
|---|---|
| `compose.yml` | 서버용 compose. 빌드 없이 `quiz-launcher:local` 이미지를 실행, 메모리 상한 포함 |
| `push-image.sh` | 이 PC 에서 빌드 → 서버로 전송 → `docker compose up -d` |
| `backup.sh` | SQLite 온라인 백업, 14일 지난 백업 삭제 |

### 서버 준비 (한 번)

```sh
# 스왑 2GB (설치 · 실행 중 메모리 부족 대비)
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo "/swapfile none swap sw 0 0" | sudo tee -a /etc/fstab
echo "vm.swappiness=10" | sudo tee /etc/sysctl.d/99-quiz-swap.conf && sudo sysctl -p /etc/sysctl.d/99-quiz-swap.conf

# Docker (Ubuntu 패키지) + 로그 크기 제한
sudo apt-get update && sudo apt-get install -y --no-install-recommends docker.io docker-compose-v2
echo '{"log-driver":"json-file","log-opts":{"max-size":"10m","max-file":"3"}}' | sudo tee /etc/docker/daemon.json
sudo systemctl restart docker && sudo usermod -aG docker ubuntu

# 배치 폴더 (backups 는 컨테이너 사용자 uid 1000 소유)
sudo mkdir -p /opt/quiz/backups && sudo chown -R ubuntu:ubuntu /opt/quiz && sudo chown 1000:1000 /opt/quiz/backups

# Tailscale: 설치 → 로그인(출력되는 링크를 연다) → tailnet 안에서 https 로 공개
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
sudo tailscale serve --bg --https=443 http://127.0.0.1:8080
```

- `tailscale serve` 는 tailnet 에서 Serve(HTTPS 인증서)가 켜져 있어야 한다. 꺼져 있으면 명령이 켜는 링크를 출력하고 기다린다.
- Tailscale 로만 접속하면 오라클 방화벽(VCN Security List · OS iptables)은 열 필요가 없다. 22번(SSH)만 열려 있으면 된다.

### 서버 배치

```
/opt/quiz/
├─ compose.yml     deploy/oracle/compose.yml 복사
├─ .env            아래 예시
├─ backup.sh       deploy/oracle/backup.sh 복사
├─ backups/        백업 결과 (uid 1000)
└─ remote.git/     테스트 콘텐츠 레포(bare, uid 1000) — 실제 GitHub 를 쓰면 없음
```

```sh
# /opt/quiz/.env (테스트 콘텐츠 레포 연결)
PUBLIC_ORIGIN=https://<서버>.<tailnet>.ts.net
CONTENT_REPO_URL=/remote.git
CONTENT_BRANCH=main
GITHUB_WEBHOOK_SECRET=<openssl rand -hex 32>
GIT_AUTHOR_NAME=quiz-server
GIT_AUTHOR_EMAIL=quiz-server@localhost
```

메모리 상한 (`compose.yml`)

| 설정 | 값 | 뜻 |
|---|---|---|
| `mem_limit` | `512m` | 컨테이너가 이 이상 쓰면 컨테이너만 정리된다(서버 전체가 멈추지 않음) |
| `memswap_limit` | `1g` | 메모리 + 스왑 합계 상한 |
| `NODE_OPTIONS` | `--max-old-space-size=256` | Node 힙 상한 256MB |

포트는 `127.0.0.1:8080` 에만 열고 `tailscale serve` 가 https 로 연결한다.

### 배포 · 업데이트

이 PC(레포 루트)에서 한 줄이면 된다. 처음 배포와 앱 업데이트 모두 같다.

```sh
deploy/oracle/push-image.sh [ssh 호스트, 기본 oracle]
#  docker build → docker save | gzip | ssh 호스트 'gunzip | docker load' → 서버에서 docker compose up -d
```

첫 배포 뒤 관리자 계정을 만든다.

```sh
ssh oracle 'sudo docker exec quiz node apps/server/scripts/admin-create.ts <아이디> <닉네임> <비밀번호>'
```

### 백업

```sh
# /etc/cron.d/quiz-backup — root 로 매일 04:00(서버 시간대, 오라클 기본 UTC = 한국 13:00)
printf 'SHELL=/bin/sh\nPATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin\n0 4 * * * root /opt/quiz/backup.sh >> /opt/quiz/backups/backup.log 2>&1\n' | sudo tee /etc/cron.d/quiz-backup
```

사용자 crontab(`crontab -`)은 Ubuntu 26.04 서버에서 등록되지 않는 경우가 있어 `/etc/cron.d` 를 쓴다(root 실행이라 sudo 불필요).

결과는 `/opt/quiz/backups/quiz-YYYYmmdd-HHMM.sqlite` 이고 14일 지난 것은 지워진다. 백업 파일은 가끔 PC 로 내려받아 둔다(`scp oracle:/opt/quiz/backups/quiz-*.sqlite .`).
복원: `docker stop quiz` → `docker cp <백업 파일> quiz:/data/db/quiz.sqlite` → `docker start quiz`.

### 실제 GitHub 레포로 바꿀 때

1. 배포 키를 만들어 GitHub 레포 Deploy keys 에 "Allow write access" 로 등록하고, 개인키를 `/opt/quiz/secrets/deploy_key` 에 둔다(처음 설치 절의 2단계와 같다).
2. `.env`: `CONTENT_REPO_URL=git@github.com:APSODE/quiz-launcher.git`
3. `compose.yml`: `./remote.git:/remote.git` 줄을 지우고 `./secrets/deploy_key:/run/secrets/deploy_key:ro` 를 추가한다.
4. 기존 작업 사본(테스트 레포 clone)을 지워야 새 레포를 clone 한다. DB 는 그대로 둔다.
   ```sh
   cd /opt/quiz && sudo docker exec quiz rm -rf /data/content && sudo docker compose up -d --force-recreate
   ```
5. GitHub webhook 을 등록한다(처음 설치 절의 webhook 표).

**webhook 제약**: Tailscale 로만 열어 두면 GitHub 가 서버에 닿지 못해 webhook 이 오지 않는다. 둘 중 하나를 고른다.
- `tailscale funnel` 로 `/api/webhooks/github` 경로만 인터넷에 공개한다(tailnet 에서 Funnel 을 켜야 한다. 나머지 화면은 tailnet 전용으로 둔다).
- webhook 없이 쓰고, PC 에서 push 한 뒤 관리자 화면 → 콘텐츠 → 새로고침을 누른다. 서버의 승인 커밋은 pull 후 커밋하므로 이 방식으로도 꼬이지 않는다.

### 주의

- **이 서버에서 `docker compose build` · `--build` 를 하지 않는다.** 이미지는 항상 `push-image.sh` 로 보낸다.
- 오라클 Always Free 인스턴스는 일정 기간 CPU · 네트워크 · 메모리 사용률이 낮으면 유휴로 보고 회수될 수 있다. 이 앱은 가벼워 해당될 수 있으므로 Pay As You Go 계정 전환(무료 한도 안에서는 과금 없음)을 권한다. 정확한 기준은 오라클 문서에서 확인한다.
- 회수 · 삭제에 대비해 백업 파일을 서버 밖에도 둔다. 문제 내용은 git 에 있으므로 DB 만 챙기면 된다.
